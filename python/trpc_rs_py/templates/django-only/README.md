# {{name}}

Generated by `trpc-py init --template django-only` — a Django backend
serving a tRPC router with end-to-end TypeScript types for the official
`@trpc/client`, plus a REST + OpenAPI surface.

## Layout

- `server.py` — one-file Django app: settings configured inline, tRPC under
  `/trpc` via `trpc_urlpatterns` (the sync view), REST + OpenAPI under `/api`
  via `asgi_view`. A real project splits this into `settings.py` / `urls.py`
  / `wsgi.py` — the trpc_rs_py wiring stays identical.
- `app-router.d.ts` — the generated router type your TypeScript app imports.

## Run

```bash
pip install trpc-rs-py django
python server.py
```

## Live type sync

While you edit Python, regenerate `app-router.d.ts` on every save:

```bash
trpc-py dev --app server:router --out app-router.d.ts
```

## Sync vs async views

This starter uses the sync view (`trpc_urlpatterns(router)`), the right
default for WSGI deployments. Under ASGI (`get_asgi_application` + uvicorn),
switch to the async views for real SSE backpressure and no worker threads:

```python
(*trpc_urlpatterns(router, asynchronous=True),)
(path("api/<path:path>", asgi_view_async(mount_rest(router, ...))),)
```

## Call it

```ts
import { createTRPCClient, httpBatchLink } from "@trpc/client";
import type { AppRouter } from "./app-router";

const client = createTRPCClient<AppRouter>({
  links: [httpBatchLink({ url: "http://127.0.0.1:8000/trpc" })],
});

await client.greeting.query({ name: "world" });
await client.create_user.mutate({ name: "Ada" });
```

The `greeting` procedure is also a REST endpoint:
`curl http://127.0.0.1:8000/api/greeting/world`, and the OpenAPI document is
at `http://127.0.0.1:8000/api/openapi.json`.
