# migrate-from-node

An existing Node tRPC app with two procedures moved to Python, one call site
at a time — the [`@trpc-rs-py/link`](../../packages/link) migration link
routes each operation to Node or Python by path, and `MergedAppRouter` merges
both router types so the client stays fully typed for migrated **and**
unmigrated procedures.

## Layout

- `node-server.ts` — the "existing" Node tRPC app (`@trpc/server` standalone
  adapter): `posts.list`, `posts.byId`, `users.me`.
- `app.py` — the FastAPI app holding the moved procedures: `posts.byId`
  (same wire path — the frontend is untouched) and `py.posts_search`
  (under the link's `py.` prefix).
- `client.ts` — a single `createTRPCClient` over `migrationLink`.
- `app-router.d.ts` — Python router types, generated by `generate_types.py`.

## Run it

```bash
# Python server (repository root, after `uv run maturin develop --release`):
uv run --project . uvicorn --app-dir examples/migrate-from-node \
  app:app --port 8000

# Node server:
cd examples/migrate-from-node
pnpm install
NODE_SERVER_PORT=3010 node node-server.ts

# Client (another terminal):
NODE_URL=http://127.0.0.1:3010 PYTHON_URL=http://127.0.0.1:8000/trpc \
  node client.ts
```

Expected output: `users.me` is answered by Node, while `posts.byId` and
`py.posts_search` come from the Python server — all through the one client.

## How routing works

```ts
migrationLink({
  nodeUrl: "http://127.0.0.1:3010", // Node keeps serving everything else
  pythonUrl: "http://127.0.0.1:8000/trpc",
  procedures: ["posts.byId"], // same-path moves route to Python
  // prefix: "py"                         // py.* routes to Python (default)
});
```

Paths are never rewritten — what the client calls is what the server sees.
Subscriptions route through `httpSubscriptionLink` on the chosen side, so a
migrated subscription streams from Python over SSE with no Node hop.
